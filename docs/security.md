# Security and dataset handling

The protected deployment uses same-origin HTTPS, revocable session tokens with only hashes stored in the database, HttpOnly and SameSite=Strict cookies, 15-minute administrator sessions, origin checks on write requests, and shared Redis limits. Administrators sign in with email and an Argon2-hashed password. The production app disables interactive API docs, restricts Host headers and adds CSP, HSTS, no-store API caching and anti-framing headers.

Public complaint intake remains available. Public analysis uses the submitted text and exposes no duplicate lookup against private records. The production API and request middleware cap uploads before parsing, allow one media part, bound concurrent inference, enforce file signatures and decoder restrictions, and keep input files transient. The backend redacts common Bangladeshi phone, NID and email patterns before saving or scoring complaints. Pattern-based redaction misses context-dependent identifiers such as names and addresses. Avoid collecting these in text and require an independent privacy review before any public dataset release. Older stored rows are not retroactively sanitized.

## Configure a production host

1. Set `ALLOWED_HOSTS` to the exact DNS name used by the HTTPS reverse proxy and keep `CORS_ORIGINS` empty for same-origin operation. Keep the API port behind that proxy. Enforce edge request limits, timeouts and rate limiting there. Compose disables proxy-header handling, so per-IP limits inside the app see the proxy address until the operator deliberately configures Uvicorn to trust only the actual proxy and configures that proxy to replace forwarded headers.
2. Generate `JWT_SECRET` with `python -c "import secrets; print(secrets.token_urlsafe(48))"` and store it in your host secret manager. The app uses this secret to sign sessions and hash identifiers for rate control. Do not publish or log key material. Production refuses initialization when prerequisites are missing.
3. Set `CIVICAI_MODEL_MANIFEST_SHA256` from the release provenance and verify the ZIP checksum when available. Do not recalculate a trusted digest from an untrusted download. Use the bundled `docker compose up --build` or managed equivalents with protected Redis, least-privilege PostgreSQL and volume/backups encrypted by the operator. Redis availability is required for authentication and rate-limited operations. Use provider TLS for external Redis/PostgreSQL. Do not expose Redis publicly.
4. Create the administrator in the running service with `docker compose exec civicai python -m backend.scripts.create_admin`. Set a unique password of at least 15 characters. For hosted first-time setup, use the short-lived setup code configured by the operator.
5. File uploads run a native decoder. For higher assurance on a public host, use a separately isolated private media worker with egress blocked at the OS or cluster level, no inherited database secrets, read-only model files and a bounded queue. The supplied deployment caps body size and concurrency and restricts permitted audio protocols and file formats. It runs media in the API service, so a decoder compromise shares the API process boundary. Evaluate a managed WAF and DDoS filtering at the hosting edge when deploying publicly.

## Dataset handling

- Keep complaint submissions, annotated raw reports, precise coordinates, test snapshots and model training extracts outside the static document root. Store them in restricted research storage. The release contains checksums, evaluation aggregates, empty annotation templates and model artifacts.
- Private tracking needs a high-entropy key and yields status-level information. Admin endpoints guard full report details, locations, duplicate review and audit notes. CSV export is for administrators on a connected backend and neutralizes initial spreadsheet formula characters. Exported admin data remains private.
- Publish only approved, aggregate results with sufficient group counts. Check licenses, anonymization and reidentification risk before releasing any row-level research data. Keep traceable evidence links in a separately restricted folder. Cap access to backups and test recovery. Rotate compromised admin credentials and review access logs at the trusted edge.
- Pinned SHA-256 verification protects model loading against modification of a trusted package. A co-located untrusted manifest cannot confer trust. Do not load third-party joblib files. Many model/tokenizer dependencies contain native code and should be updated and rescanned.

The package was tested locally with SQLite and real model assets. Production Redis, TLS termination, WAF, backup encryption and host isolation still need validation on the chosen deployment. Dependency scans and defensive regression tests do not establish penetration-test coverage.
